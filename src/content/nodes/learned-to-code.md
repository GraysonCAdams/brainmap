## Problem

There wasn't one, and I want to be accurate about that rather than build a founding myth. Nobody set me a task. What existed was a website my father put up for me, and a kid who wanted to change it.

## Constraints

I did not make the thing I was editing. That turns out to be the important detail. The starting position was not a blank file and a tutorial, it was **someone else's working code that I was allowed to break**, which is a very different and much better place to begin.

There was also nobody to ask. Whatever I learned came from opening something that already worked and altering it until it broke or improved.

## Approach

View source, essentially. Change a value, reload, see what moved. That is a poor way to learn theory and an excellent way to build the instinct that everything on a screen is made of something you can open and edit.

The site's own earliest surviving capture, from 2004, is written in my voice: *"This is my website as I complete first grade; the site began when I was in Kindergarten. It is here for you to enjoy and for me to learn some web design."* The words are mine. The HTML at that point was not.

## Edge cases considered

Nothing consciously. But the habits date from here and they are the ones I still have.

By around nine I had added scripts to block right-clicking, with a note asking people not to take my content. That is a child's first collision with the fact that anything you serve, you have already given away.

By twelve I was administering my own hosting, and the clearest artifact is a support ticket where I had set a directory to permissions 777, watched the folder vanish, and wrote in to say **"the folder entirely disappeared from view. Yet, it is still there."** I was wrong about the cause and completely right about the distinction. *Unreachable* and *gone* are different failures with different fixes, and noticing that at twelve is close to the whole job I do now.

## Tradeoffs

Learning by imitation left real gaps. I could build things well before I could explain why they worked, and it took years of professional work to backfill theory under habits I already had.

The compensating advantage is that I have never once believed a system is a black box. If it renders, it is made of something, and that something can be opened.

## Outcome

Everything else on this map. The domain itself is the next node over, and it ran for eighteen more years after this.

I would rather be honest about the boundary than claim the earlier date: the first version of that site was a gift, not a project. My own code starts with what I did to it afterward.
